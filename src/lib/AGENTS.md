# src/lib rules
- Scheme UI shares `scheme-rules.ts`; amounts/free lines come from quotes, benefits sum persisted order-line fields, and split names come from quote.split. Why: one server-owned source of discounts and fulfilment.

- `otp.functions.ts`: resolve mobile identities customer-first, with staff fallback only when `check_pin_login` returns `not_registered`; OTP rows use `app_login` and the selected identity. Always use the phone's real device ID, preserve database lock/revocation behavior, consume OTP after link creation, and create customers only for new numbers. Record the session before checking `sales_whoami`; staff enter this app only with confirmed sales rights. Why: staff salesmen have no own customer and session-protected RPCs reject unrecorded logins.

- `catalogue.ts` `fetchCatalogue()` is the only catalogue source (authenticated get_home RPC, persisted ten-minute copy, 60-second freshness, stale copies refresh quietly via onCatalogue; `{force:true}` forces network; `arrangeCatalogue` sorts by category then product sort_order and drops empty categories); favourites via `toggle_favourite`; Home content from `app_hero`, `app_home_sections`, `product_categories`, `app_banners`; null image URLs use bundled fallbacks by product code. Why: never query price-plan tables directly or poll the entire catalogue.
- `registration.functions.ts` reads; writes via `start_registration`, `add_customer_document`, `submit_registration`; docs upload to `customer-docs` at `<customer_id>/<uuid>.<ext>`. Why: existing schema only.
- `profile.functions.ts` `clearMyPhoto` is the only way to null a photo (RPC coalesces null; no own-update RLS). Avatars: `avatars` bucket at exactly `<user_id>/avatar-<timestamp>.jpg`, 512×512 JPEG < 300 KB, old file deleted after swap. Why: backend constraints.
- `query-staff.functions.ts` `getStaffNames`, `invoice.functions.ts` `getInvoiceFirm`, `payments.functions.ts` `getFirmPaymentInfo` and `pod.functions.ts` `getPodUrls` verify access via RLS, then read `user_profiles` / `firms`+`firm_bank_accounts` / `trip_stops`+storage with the service role. POD signature/photo URLs must be signed server-side: the `operations` bucket is staff-only for reads, so the browser cannot sign them. Why: customers cannot select those rows or objects.
- `billing.ts` reads invoices/receipts and `customer_open_bills`/`customer_statement` RPCs. Why: RLS scopes them to the customer.
- `orders.ts`: own-order filter relies on `customer_id` in ORDER_SELECT; keep it in sync with `fetchMyOrders()`. Shared order/status label helpers live in `order-format.ts`. Why: RLS also returns distributor-routed rows.
- `app-settings.ts` is the only reader of Command Center `app_settings`; screens use `useAppSettings()` and its pure rule helpers. Why: one cache, testable rules.
- `ist.ts` is the only source of "today", day starts/ends and month ranges: all day boundaries and date displays are Asia/Kolkata (`istToday`, `istDayStart/End`, `IST_TZ`), and date-only strings count as their own day. Why: a payment at 1:30 AM IST must belong to that IST day, not the previous UTC day.
- `native.ts` wraps Capacitor and must stay a no-op on the web; plugins are imported dynamically. Why: the web app must not depend on native APIs.
- `quoteMyOrder` re-reads `credit_status` per firm in the quote (firm-specific limit beats the customer limit, as in `_create_orders`). Why: the firm-less quote figure disagreed with what the server holds.
- Demo behaviour (`useIsDemo`) comes only from `customers.is_demo`, never `user_profiles.is_demo`. Why: QA accounts use fixed-PIN login but must behave like real shops.
- Every customer-side read of a customer-owned table filters explicitly by the caller's own customer: browser code via `ownCustomerFilter()`/`getMyCustomerId()` (`my-customer.ts`, cached `my_customer_id`, cleared on sign-out), server fns via `ownCid(context.supabase)` (`own-customer.ts`). Why: staff who are also customers see all rows through RLS.

- Speed caches: `/sw.js` (vite-plugin-pwa generateSW, registered only by `src/lib/sw-register.ts` on published hosts) precaches hashed assets and uses NetworkFirst for pages; the auth gate reuses its last check for 5 min in memory and up to 24 h from localStorage on a cold open, re-checking in the background and applying status changes through router invalidation (`src/lib/gate-cache.ts`, cleared on auth change and registration refresh); Home's Khata strip, address header and Home chat badge read `get_home()` extras (`onHomeExtras`); Khata/orders show `src/lib/swr-cache.ts` copies first, cleared on sign-out. Checkout prices always come from the server quote. Why: instant page changes and 2nd opens on slow 4G.
- `dispatch.ts` reads `my_order_dispatch` for the "On the way" card (map pin only when live_location) and bill GST details; GSTIN auto-fill calls the `gst-docs` function once per GSTIN and fills only empty fields. Why: transporter vehicles have no live app; GST lookup must never block registration.
